# EZCH Update 1.8.0 Premium — отчёт, 15.10.2026

Реализуется только EZCH Update. Материалы Евы изучены как отдельный продукт; голосовой ассистент и изменение рабочего стола в этот выпуск не входят. Основа оформления — предоставленный красно-чёрный референс центра приложений.

## Изменения

- AMOLED-интерфейс с красными акцентами и векторными дугами, три колонки, шесть основных разделов, русский UTF-8, часы и дата. Заголовок больше не содержит рекламного подзаголовка. Иконки навигации рисуются векторно.
- Основные 20 позиций имеют заданные категории и порядок. Vimu находится в инструментах; YouTube, RUTUBE и VK Видео — в видеосервисах. RuStore сохраняется среди всех приложений. Всего 21 карточка; наличие карточки не означает наличие проверенного APK.
- Реальные статусы PackageManager, выбор нескольких APK, установка/обновление/открытие, история результатов, экспорт краткой диагностики. Ошибка запуска приложения отображается пользователю.
- Оригинальные иконки загружаются из установленного приложения, проверенного индекса или локального снимка. Исправлен адаптивный значок Zona. Для сетевых иконок проверяются допустимый источник, SHA-256, размер и разрешение.
- Заставка EZCH Cinema Premium с четырьмя последовательно подсвечиваемыми точками; Auto/Premium/Lite, уменьшение анимаций на слабых устройствах.
- Сохраняемая последовательная очередь, ожидание окончательного результата Android, восстановление после перезапуска, отмена, повтор ошибки, собственное обновление последним. ID сеанса сохраняется до commit, чтобы пережить замену процесса при самообновлении.

## Автоматическое напоминание пользователю

По умолчанию включена фоновая проверка каждый час; доступны 1, 6 и 24 часа. WorkManager хранит задание после закрытия процесса и перезагрузки. Интервал ориентировочный: Android может отложить работу при сне, отсутствии сети или после принудительной остановки. Это ограничение [WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work).

Уведомление создаётся только для уже установленных приложений с более новой проверенной версией в индексе. Текст «Пора обновить приложения • N», список приложений, переход в раздел «Обновления». Одна и та же комбинация пакетов/версий/SHA не вызывает повторного сообщения. После обновления список пересчитывается, пустое уведомление удаляется. Отказ в разрешении не помечает версию как уже показанную.

На Android 13+ требуется системное разрешение уведомлений. Его можно выдать при первом запуске или из настроек. Есть отдельное отключение напоминаний и переход в настройки уведомлений Android.

Добавлено TV-расширение уведомления. Для оболочек без панели уведомлений дополнительно показывается короткое стандартное текстовое напоминание Android поверх рабочего стола. На Dongle G 4K с установленным EZCH Launcher баннер визуально подтверждён снимком экрана. Проверка использовала тестовую запись уведомления; это не выдаётся за обнаружение реального нового стороннего APK. Постоянная карточка/счётчик непосредственно внутри стороннего лаунчера в этот APK не добавлялись. Разрешения наложения поверх окон и Accessibility не требуются.

Предварительная загрузка отключена по умолчанию. Если её включить, проверяются и сохраняются байты APK; установка остаётся действием пользователя с подтверждением Android.

## Установка и Play Protect

Сохраняются исходные идентификаторы: `com.example.ezchupdate.tvtest` для TV и `com.example.ezchupdate` для ранней версии. Оба APK подписаны прежним сертификатом:

`ea0e9a1aad77b1fb42f32644a7386131ceed43e07464dcde22754691e70cc602`

Номер финального выпуска — `versionCode 30`, `versionName 1.8.0`. Ранее на телевизоре была версия 1.7.2, код 28. Промежуточная подписанная сборка 1.8.0, код 29, установлена через нормальный PackageInstaller с системным подтверждением. Получен `STATUS_SUCCESS`, PackageManager подтвердил замену версии. Установку инициировала отдельная тестовая сборка установщика; это отдельно от проверки самообновления.

До открытия сеанса проверяются карантин, обязательные SHA-256/размер/сертификат, packageName, versionCode и versionName, minSdk, ABI, цельность APK и отсутствие обязательных split-пакетов, совместимость подписи с установленной версией и отсутствие понижения версии. HTTPS обязателен. Очередь не считает отмену или ошибку успехом.

Разрешение установки запрашивается только штатным экраном Android. На Android 12+ используется `USER_ACTION_REQUIRED`. Удалено неиспользуемое разрешение foreground service, которое добавляла зависимость. Нет QUERY_ALL_PACKAGES, Accessibility, root, автоматических нажатий в продукте и отключения Play Protect.

Предыдущий отчёт `TV82_INSTALL_TESTING.md` фиксирует блокировку 09.10.2026 с `INSTALL_FAILED_VERIFICATION_FAILURE`. Подпись и разрешения сами по себе не доказывают причину решения Play Protect. В проведённой сегодня обычной установке промежуточного APK блокировки не было. Это не универсальная гарантия и не заключение об исправлении репутации приложения. При повторной блокировке следует сохранять сообщение/хеш/сертификат и использовать [официальную процедуру Google](https://developers.google.com/android/play-protect/warning-dev-guidance); защиту не обходить.

## Google Drive и отсутствующие APK

Папка `1lC9hjcz7phWG-fQADjO54aH9Wg2RPrrB` повторно прочитана через подключённый Google Drive: 19 APK. YouTube и Panda Vision в ней отсутствуют. Task Killer 4.0.2 есть, но совпадает с карантином.

Серверный индекс переведён с разбора HTML на Drive API v3. Обрабатываются все страницы; проверяются parent, ID, размеры и время изменения. Папка перечитывается после проверки APK. Ошибка, неполный ответ, дубликаты, изменение папки во время проверки или неподдерживаемая вложенность сохраняют предыдущий полный каталог. APK проверяются aapt2/apksigner, версии сравниваются по манифесту, выбирается старшая версия. Сохраняются опубликованные релизы проекта. Иконки формируются отдельно и получают хеш.

В APK нет API-ключа или OAuth-токена. GitHub Actions ожидает секрет `GOOGLE_DRIVE_API_KEY`, ограниченный Google Drive API. На момент проверки секрет отсутствовал; консоль Cloud не загружала API/список проектов. Живой автоматический обход через серверный ключ пока не подтверждён. Периодическая загрузка уже опубликованного GitHub-индекса в приложении работает независимо от этой настройки.

Для завершения подключения: включить Google Drive API в проекте EZCH Catalog Index, создать ключ с ограничением только Drive API, добавить его в Actions secrets репозитория и запустить `Sync application catalog from Google Drive`. Не помещать ключ в исходники или APK. Успех подтвердить реальным добавлением/сменой APK, выполнением workflow и появлением новой версии в индексе.
