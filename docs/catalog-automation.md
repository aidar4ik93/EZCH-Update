# Автоматическое обновление папки apps

Источник — публичная папка владельца:
https://drive.google.com/drive/folders/1lC9hjcz7phWG-fQADjO54aH9Wg2RPrrB

## Как обновляется каталог

Cloudflare Worker `ezch-drive-catalog` проверяет папку каждую минуту. Он сравнивает идентификатор, имя, размер и время изменения каждого APK с опубликованным снимком `catalog-source.json`. Для незавершённой загрузки используется повторная проверка стабильности. При изменении запускается существующий GitHub workflow `sync-google-drive-catalog.yml`.

GitHub скачивает и проверяет APK, читает настоящую версию и пакет, проверяет подпись и SHA-256, извлекает оригинальные иконки. После успешной проверки всей папки каталог, иконки и снимок источника публикуются одним коммитом. Сохраняются актуальные выпуски EZCH Update, Launcher Classic/Scene и Baya, даже если в Drive лежат старые APK.

Это не мгновенные push-уведомления Google Drive: обычно требуется 1–2 минуты на обнаружение изменения плюс время проверки APK на GitHub. Очередь GitHub и доступность Google Drive могут увеличить задержку. Работа ПК владельца для этой цепочки не нужна.

В установленном EZCH Update 1.9.1 список автоматически перечитывается при возвращении в приложение и каждые пять минут, пока экран открыт и нет активной установки. Для немедленного чтения уже опубликованного каталога остаётся кнопка «Проверить обновления». Пересборка APK установщика для этой серверной автоматизации не требуется.

Резервное расписание GitHub проверяет метаданные каждые пять минут. Если папка, каталог и иконки не изменились, скачивание APK и установка Android SDK пропускаются. Раз в сутки выполняется полная перепроверка байтов, в том числе на случай замены файла с сохранёнными метаданными.

## Защита

- Недоступная, пустая, частичная или неожиданная страница Drive не заменяет рабочий каталог.
- Изменение папки во время проверки прерывает публикацию.
- Работающий workflow не запускается повторно каждую минуту; ошибки проверки повторяются с задержкой.
- Если репозиторий изменился во время проверки, старый снимок не записывается поверх нового релиза. Наблюдатель повторит проверку.
- Удалённые из папки обычные приложения исчезают из каталога после успешной проверки. Проектные релизы EZCH сохраняются.
- Поля иконки и её хеша публикуются вместе, PNG проверяется по размеру и SHA-256.

Публичный статус: https://ezch-drive-catalog.ezch-aidar.workers.dev/status
В нём нет токенов. `lastCheckAt` обновляется не чаще раза в десять минут при неизменной папке; это ограничивает записи KV. `lastScheduledAt` подтверждает выполнение таймера.

## Развёртывание и ручной запуск

Код и тесты: `automation/drive-watcher/`. Скопируйте `wrangler.example.jsonc` в `wrangler.jsonc`, укажите свой аккаунт и отдельное KV-пространство `STATE`. Задайте через `wrangler secret put` секреты `GITHUB_TOKEN` (право запускать Actions в этом репозитории) и случайный `ADMIN_TOKEN`. Секреты не добавляются в исходники, APK, адреса запросов или ответы статуса.

Размещение: `wrangler deploy --config wrangler.jsonc`. Один Cron Trigger: `* * * * *`. Не требуется менять службу авторизации Яндекса.

Ручная проверка: авторизованный `POST /check`. Для полной проверки цепочки — `POST /check?force=true`. В заголовке нужен `Authorization: Bearer <ADMIN_TOKEN>`. Публичные запросы без этого секрета получают 401.

Локальные тесты:

```
python -m unittest discover -s scripts -p 'test_*.py' -v
node --test automation/drive-watcher/tests/*.test.mjs
```

Текущий безопасный парсер публичного Drive отклоняет вложенные папки, пагинацию и списки от 50 элементов. Он останавливает обновление вместо публикации неполного каталога. Для более крупной папки требуется перейти на авторизованный Drive API с полной пагинацией.
